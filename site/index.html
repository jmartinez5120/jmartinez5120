Software Architecture

“As AI makes code abundant, architecture becomes the discipline that matters most. Generating software is no longer the hard part; designing systems that last is.”

John R. Martinez

I own systems end to end: the roadmap, the data model, the failure modes, and the runbook the on-call team actually uses. Most of my work is moving platforms that have outgrown their original design onto something the team can run without holding its breath, one piece at a time.

CQRSReads and writes had very different shapes and volumes. PostgreSQL is the source of truth for writes; MongoDB serves high-volume lookups.
Change Data CaptureThe read model had to stay current without dual-writes, so changes stream from Postgres via Debezium + Kafka Connect.
Event-Driven ArchitectureTeams kept blocking on each other's services. Kafka let them react to events instead of calling synchronously.
Strangler FigA 1996 Oracle stored-proc SSO system couldn't be rewritten in one shot, so we replaced it route by route with no downtime.
MicroservicesOne deploy shouldn't gate every team, so responsibilities are split into independently shippable Spring Boot services.
Reactive servicesUnder acquisition-flow traffic, thread-per-request fell over. Non-blocking I/O kept latency flat under load.

How I Work With AI

An agent starts every session with no memory of the last one, so I keep the thinking in writing. Every stage leaves behind a document the next stage, and the next engineer, can pick up.

Research

Dig into the problem, prior art, and constraints with the agent before any code.

→ PRR brief

Design

Turn the research into an approach and weigh the trade-offs out loud.

→ Design doc + ADRs

Architect

Define structure, data model, and interfaces before implementation.

→ CLAUDE.md / AGENTS.md

Execute

Agents implement against that context; I review, correct, and iterate.

→ Small PRs + runbooks
