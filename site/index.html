Architecture in Production

“As AI makes code abundant, architecture becomes the discipline that matters most. Generating software is no longer the hard part; designing systems that last is.”

John R. Martinez

I own systems end to end: the roadmap, the data model, the failure modes, and the runbook the on-call team actually uses. I reach for the simplest pattern that solves the specific problem, and I name the trade-off before committing to it.

CQRS

Enterprise identity · Tier-0

Constraint
Reads and writes had very different shapes and volumes.
Decision
PostgreSQL is the source of truth for writes; a MongoDB read model serves high-volume lookups.
Trade-off accepted
Eventual consistency between the write and read sides, in exchange for scaling each independently.

Event-Driven Architecture

Enterprise identity · Tier-0

Constraint
Transactions and data without a critical SLA, and data that must reliably reach downstream applications such as BigQuery data lakes.
Decision
Publish them through Kafka as events instead of synchronous calls.
Trade-off accepted
Asynchronous delivery and a broker to operate, in exchange for decoupled, durable delivery.

Microservices

Enterprise identity · Tier-0

Constraint
One deploy must never put the whole Tier-0 application at risk.
Decision
Small, independently deployed services, each with a single responsibility.
Trade-off accepted
More moving parts to operate, in exchange for isolated failures and changes that ship without disrupting the whole platform.

Selected Engineering Projects

Real-Time Communication Infrastructure

TapeRoom

Chat-core MVP on TestFlight (iOS) · macOS and web clients

An end-to-end encrypted communication platform for financial market participants, integrating real-time messaging with contextual market intelligence: a ticker typed into a message becomes a live quote card.

Problem
Market conversations need real-time delivery and live prices without giving the server access to what people say.
Architecture
Go modular monolith split into api (REST), gateway (WebSocket connections, fan-out through Redis pub/sub, presence) and worker (market data polling and live ticks).
Security
Signal-protocol E2EE on every message, multi-device, with a Rust crypto core. The server stores ciphertext and routing metadata only. Sign-in with passkeys (WebAuthn), TOTP step-up, and account recovery.
Trade-off
Market cards are separate requests the platform can see, by design, so quotes can be resolved and filled in server-side while message content stays encrypted.
Performance
Data is read Redis → Postgres/Timescale → provider; an external provider is called only when stored data can't answer, always behind one provider-agnostic interface.
Stack
Go · WebSocket · Redis · PostgreSQL · TimescaleDB · Rust (libsignal) · SwiftUI · React · Google Cloud (Cloud Run, GKE-ready)

Supply Chain Intelligence & Dependency Modeling

Quartermaster

Personal research platform

An investment intelligence platform that models supply chain relationships, corporate dependencies, and cascading risks across interconnected industries. When one company is disrupted, it ranks which others are exposed, with confidence scores and the evidence behind them.

Problem
Supply chain exposure is spread across filings, entity registries and economic data, and a shock propagates several hops before it shows up in a price.
Architecture
Independent collectors write raw public data to PostgreSQL and publish events; a single aggregation pipeline resolves entities and builds the relationship graph in Neo4j and the search index in Elasticsearch.
Modeling
Cascade impact = relationship strength × shock magnitude × 1 / hop distance, searched breadth-first up to 4 hops and pruned below 0.1.
Trade-off
2–4 hop cascade paths are materialized as graph edges ahead of time, trading storage and a daily batch for fast reads.
Consistency
Only the aggregation pipeline writes to Neo4j and Elasticsearch, so the graph and search index are always derived from one source of truth.
Stack
Java 21 · Spring Boot 3 · WebFlux · Spring Batch · PostgreSQL · Redis · Neo4j · Elasticsearch · React · Cytoscape.js

How I Engineer

First-Principles Thinking

Understand the underlying problem before selecting the technology.

Reliability by Design

Treat failure as an expected system condition, not an exceptional event.

Performance Through Measurement

Measure, benchmark, and optimize based on evidence rather than assumptions.

Simplicity Over Complexity

Prefer understandable, maintainable solutions over unnecessary abstraction.

End-to-End Ownership

Take responsibility for systems from architecture and implementation through deployment and operation.

Continuous Exploration

Experiment with emerging technologies to understand their capabilities, limitations, and practical applications.
